## Fixed

- [Blocker, fixed in `7c1d86f`] `apps/bff/src/services/optimiser.ts` — when no version had
  gold-labeled predictions on the optimiser half (reachable via the agent `start_optimiser`
  tool, which has no gold/threshold guard), `parentMetrics` stayed null, the finished parent
  task was returned again, and the loop spun without waiting, re-reading project state

  nothing to score against.

## Major (for the External Agent)

- `apps/bff/src/services/work.ts:18` + `apps/web/src/app/prompt/page.tsx:75`,
  `apps/web/src/app/prompt/edit/page.tsx:77` — Save/Create calls `scoreVersion` directly, so
  paid scoring starts even when `SetupVersion.autoStart` is off or a cap applies; no
  `auto_start` audit, no waiting-for-click button. `tick`/`waitingStarts` already implement
  the intended path.
- `apps/bff/src/services/evaluation.ts:58` — automatic eval/optimiser tasks are created with
  no `budgetUsd`, so labeling's 120% pause never applies to automatic starts; the $1/$5 caps
  are pre-flight estimates only (up to 10 sampled examples, fixed 150 output tokens).
- `packages/domain/src/auto-start.ts:37` — `autoSpendUsd` ignores `try_template` spend (it
  saves no run/optimisation record), so repeated automatic `try_template` calls never move
  the $5 project cap.
- `apps/bff/src/services/work.ts:85` — `tick` checks all due starts against one stale
  snapshot, so several starts in one tick can jointly pass the $5 cap (for example at $4.90
  prior spend: score on both models plus an optimiser run).
- `apps/bff/src/services/evaluation.ts:66` — a task's `createdBy`/`auto` flag is fixed at
  creation; automatically resuming a user-started paused task books the resumed spend as
  non-automatic, escaping the $5 cap.
- `apps/bff/src/services/optimiser.ts:110` — parent labeling cost is not added to
  `run.costUsd`, so an auto-started optimiser's first eval pass is missing from reported
  cost and from the automatic-spend total.
- `apps/bff/src/services/training.ts:26` — `labelTestSet` reuses an existing test task
  matching only `exampleIds.length`; after a re-split with the same count but different
  members it returns a task over the old examples and the current test set never gets
  answers.
- `apps/bff/src/services/training.ts:75` — final-run planning treats any saved prediction
  (including invalid output with `answer: null`) as a saved answer; those test examples are
  excluded from `toLabel` even when the user ticked "label the rest" and end with no label.
- `apps/llm-gateway/src/gateway.ts:113` — on error, `permit.release()` pumps the FIFO queue
  before `onRateLimited()` runs (line 130), so one queued call can be granted and sent
  during the 429 hold, defeating the halving for at least one call per 429.
- `apps/llm-gateway/src/limiter.ts:147` — `schedule()` keeps any pending timer, so a stale
  60s window timer can override a shorter Retry-After wakeup; recovery delayed up to a
  full window.
- `apps/labeling/src/labeling.ts:291` — `retryFailed()` clears `failedExampleIds`/`failed`
  and sets `state: 'queued'` before taking the lock; on an already-running task it corrupts
  the active run's failure bookkeeping and loses recorded failed ids.
- `apps/labeling/src/labeling.ts:184` — prediction dedupe is a non-atomic snapshot then
  insert, and the lock is per-task only; two concurrent tasks for the same
  version/endpoint/settings both pay and insert the same deterministic prediction id as
  separate documents.
- `apps/labeling/src/labeling.ts:207` — `checkStop()` runs only after an example finishes
  (no 2s timer), so a Stop from another tab is not seen while a call is queued in the
  limiter, in gateway retry sleeps, or in a long model call; that paid call still completes
  and saves.
- `apps/telemetry/src/telemetry.ts:25` — metric label values are denylist-filtered only,
  not restricted to the declared small/fixed sets; values like `pr_1` or an email pass
  verbatim (up to 48 chars), so the no-ids-as-labels guarantee is not enforced at runtime.
  Current in-repo callers pass registry/enum values, so no observed leak.
- `apps/telemetry/src/telemetry.ts:109` — `event()` forwards props verbatim with no runtime
  allowlist/redaction; a cast or JS caller could send prompt/chat text to the sink (the
  stand-in persists events in localStorage). No in-repo caller does this; e2e reports
  leaks: 0.
- `scripts/check-boundaries.mjs:32,40,71` — the boundary checker is specifier-string based:
  it misses side-effect imports, `require()`, dynamic imports, files outside the listed
  `src` dirs, and `.cjs`/`.jsx` files; aliases in tsconfig/next.config are never inspected.
  It enforces the common cases but is bypassable.

## Minor (for the External Agent)

- `apps/llm-gateway/src/gateway.ts:128` — a final-attempt 429 never calls `onRateLimited()`.
- `apps/llm-gateway/src/gateway.ts:172` — `chatStream` bypasses retry, `onRateLimited()`,
  and token correction.
- `apps/llm-gateway/src/limiter.ts:78` — aborting a queued waiter never calls `pump()`; the
  next waiter can sit until an unrelated release or the window timer.
- `apps/labeling/src/labeling.ts:131` — startup patches `stopRequested: false` from a stale
  read, silently discarding a Stop pressed in between.
- `apps/labeling/src/labeling.ts:122` — `failedSet` is not reduced by `saved`; an example
  failed by one run and saved by another counts as both done and failed and forces
  `needs_attention`.
- `apps/labeling/src/labeling.ts:202` — failure/budget thresholds are only checked after a
  worker's example, so a resumed already-over-budget task starts up to `parallel` new paid
  calls first.
- `apps/bff/src/services/starts.ts:134` — `answerStartCard` marks the card approved before
  running and drops the fresh estimate; a failed plan leaves an unretryable approved card.
- `apps/bff/src/services/page-views.ts:175` — the agent's Training page view prices the
  final run over all train+test examples instead of using `finalRunPlan`, quoting higher
  cost/counts than the page.
- `apps/bff/src/services/page-views.ts:121` — the Setup page view omits `setup.autoStart`,
  although the switch lives on Setup step 3.
- `packages/domain/src/template.ts:236` — a `[Image N]` reference with no matching prompt
  image stays in the rendered text sent to the model, and `checkTemplate` never validates
  fixed image references, so deleting a prompt image is not blocked at Save.
- `packages/domain/src/labels.ts:18` — duplicate values in a multi-select answer are neither
  rejected nor de-duplicated and are exported into training rows.
- `apps/telemetry/src/telemetry.ts:140` — `flush()` during an in-flight flush does not drain
  events buffered meanwhile; a hide/shutdown caller can believe they were sent.
- `apps/telemetry/src/telemetry.ts:80` — `counter()` accepts `Infinity`, poisoning every
  later Prometheus exposition.
- `scripts/check-boundaries.mjs:31,27` — `TEST_EXTRA` lets every test import
  `@tsp/platform`/`@tsp/catalog` regardless of its row, and the web allowlist includes
  `@/app`, which is not in the documented table.
- `apps/web/src/app/providers.tsx:4` — `Providers` imports Astryx directly, bypassing the
  `@/ui` single touchpoint.
